# Skill、Memory 与 Documentation 迁移审计

> 文档类型：一次性迁移审计（长期保留，不进入日常读取链）
>
> 审计范围：Agent 规则、项目 Memory、Skill、Skill references、ADR、Architecture、包级合同与相关项目文档
>
> 行为基线：当前代码、测试、包公共入口与现行运行时组合

## 1. 审计方法

每个来源按以下字段分类：

- **Role**：Agent Rule、Workflow、Validation、Memory、Current State、Architecture、ADR、Lesson、Git History、Duplicate 或 Obsolete。
- **Canonical owner**：重构完成后唯一维护该信息的位置。
- **Disposition**：retain、normalize、route、migrate、replace、retire 或 record-only。
- **Verification source**：用来核对当前事实的代码、测试、公共入口、包合同或专题文档。

迁入 Memory 的内容必须同时满足：当前可验证、非显而易见且重新发现成本高、会影响未来实现正确性。

## 7. 重复、过期与冲突结论

1. `AGENTS.md`、`AGENT_MEMORY.md` 和 maintenance Skill 同时维护包 ownership、当前迁移状态、安全规则和验证命令，是默认上下文膨胀的主要来源。
2. `AGENT_MEMORY.md` 自称不是 changelog，但包含大量日期流水、完成阶段、测试通过率和一条机器本地 `file://` 路径；这些不进入新 Memory。
3. `AGENT_MEMORY.md` 中“新 UI 仍进入 App legacy feature path”以及“`main.dart` 负责组合服务”的描述已与当前 package ownership 和 AppBootstrap/AppRuntime 边界冲突，属于 Obsolete。
4. Maintenance Skill 同时承担项目百科、Feature 当前状态、长测试清单和工作流，且内部存在 Terminal、SFTP 和 Task Routing 重复条目。
5. `CLAUDE.md` 和 Skill 宣称根 `AGENTS.md` 是完整规则/架构/验证权威，而新治理模型要求 Skill 管规则、Memory 管当前知识、根文件只管启动；迁移必须原子切换这些入口。
6. `docs/architecture/MODULAR_REFACTOR_PLAN.md` 既有当前架构又有执行流水；本任务不大规模重写它，仅在新路由中将其降级为条件性参考。
7. 项目存在两个编号为 ADR-011 的 Accepted ADR；该问题留待单独任务。
